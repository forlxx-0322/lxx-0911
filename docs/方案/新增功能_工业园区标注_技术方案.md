# 新增功能技术方案：工业园区标注与客户归属

> 关联方案：`客户管理系统_实施方案.md`（阶段六 · 新疆分布地图）
> 状态：**待确认，尚未开发**

## 一、需求回顾

1. 在地图功能中把**新疆的工业园区**标注出来
2. 在**客户管理**中可以**手动**把客户划归到某个工业园区
3. 归属关系**同步显示在地图上**

---

## 二、实测结论（先看这三条，它们决定方案形态）

| 验证项 | 结果 | 影响 |
|---|---|---|
| 县级行政区划 GeoJSON（园区定位用） | ✅ 可用。新疆各地州下辖县市齐全（如阿勒泰地区 54KB，含 7 个县市中心点） | 园区可以按"所属地州 + 县市"归类统计 |
| **园区级边界 GeoJSON** | ❌ **不存在**。试探园区级边界接口返回 404 | **园区只能用「点标注」，不能用「色块边界」** |
| 园区权威名录 | ✅ 存在。《[中国开发区审核公告目录（2018 年版）](https://www.gov.cn/zhengce/zhengceku/2018-12/31/content_5434045.htm)》新疆 **84 个开发区**；[新疆发改委公告](https://xjdrc.xinjiang.gov.cn/xjfgw/c108381/201803/3ad130b35306459f9d97af82ce75f28f.shtml)；2025 年[新增 13 家自治区级园区](https://v.chinaxinjiang.cn/2025/03/17/78efc1477b674abbb4af7803097af9f2.html) | 名录能拿到，但**名录里没有经纬度** |

### 2.1 关键判断一：为什么用「点标注」而不是「园区边界」

园区不是行政区划，国家不发布标准边界数据。要拿到边界只有三条路，都有问题：

| 路径 | 问题 |
|---|---|
| 找开源边界数据 | 无权威来源，精度与完整性无保证 |
| 自己描边界 | 每个园区手工描多边形，84 个 × 每个约 30 分钟 = 约 42 小时，不现实 |
| 让用户自己画 | 实现复杂（需要多边形绘制工具），且对"看客户分布"这个目的收益极低 |

**结论**：园区以**一个点（中心位置）**存在于地图上，用图标 + 名称标签标注。这对你的实际需求（"我的客户在哪些园区"）完全够用——你不需要知道园区的边界线在哪，你需要知道客户集中在哪几个园区。

**顺带一个好处**：园区边界是"面"，需要判断客户落在哪个面里；点标注则只需要**手动指定归属**，正好符合你要求的"手动操作划归"。

### 2.2 关键判断二：最麻烦的不是地图，是「园区坐标从哪来」

84 个园区，每个都要有经纬度才能画在地图上。可选路径：

| 方式 | 可行性 | 说明 |
|---|---|---|
| 高德/百度 POI 接口批量自动取坐标 | ❌ **不可行** | 需要 API Key，且要企业实名申请；批量抓取地图平台数据也违反其服务条款（与附录 A 的合规原则一致） |
| 从政府公开文件里批量提取 | ⚠️ 部分可行 | 部分园区规划文件含坐标，但格式各异、覆盖率低，且大量是 PDF 扫描件 |
| **软件内提供坐标录入，用户按需维护** | ✅ **推荐** | 只维护你实际打过交道的园区（可能 10~20 个），录入一次长期有效 |
| 预置常见园区的**近似中心坐标** | ✅ 可行 | 按县市中心点 + 已知位置估算，**误差可能 1~5 公里**，需你人工校准 |

**推荐组合**：预置名录（84 + 13 个园区名称与所属地州/县市，无需坐标） + 用户按需录入精确坐标。**首次打开地图时，未录入坐标的园区不显示在地图上，但客户归属下拉框里已经能选**——这样你可以先归档，坐标慢慢补。

## 三、数据库设计

### 3.1 新增表 `industrial_parks`（工业园区主表）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER | 主键 |
| name | TEXT ✔ | 园区全称（如「库尔勒经济技术开发区」） |
| short_name | TEXT | 简称（地图标签用，避免拥挤） |
| code | TEXT | 园区代码（《中国开发区审核公告目录》中的代码，便于与官方名录对照） |
| level | TEXT | 级别：国家级经济技术开发区 / 国家级高新技术产业开发区 / 国家级边境经济合作区 / 综合保税区 / 自治区级园区 / 其他 |
| park_type | TEXT | 类型：经济技术开发区 / 高新技术产业开发区 / 化工园区 / 保税区 / 边境合作区 / 物流园 / 其他 |
| status | TEXT | 状态：已审核公告 / 自治区级新增 / 筹建 |
| province / city / district | TEXT | 所属省 / 地州 / 县市（用于按地州聚合统计） |
| longitude / latitude | REAL | **园区中心点坐标**（WGS84；可空，空则不上图） |
| coord_source | TEXT | 坐标来源：手动标注 / 估算 / 导入（便于日后核对精度） |
| addr | TEXT | 园区地址描述 |
| main_industries | TEXT | 主导产业（多选：石油化工 / 煤化工 / 装备制造 / 纺织服装 / 食品加工 / 有色冶金 / 新能源 / 新材料 …） |
| admin_org | TEXT | 管委会 / 运营单位名称 |
| contact / phone | TEXT | 园区招商联系方式（**仅企业公开总机，不采集个人信息**） |
| website | TEXT | 官网 |
| remark | TEXT | 备注 |
| enabled | INTEGER | 是否在地图上显示（0/1） |
| sort | INTEGER | 排序 |
| created_at / updated_at / deleted_at | TEXT | 时间戳与软删除 |

索引：`name`、`city`、`level`、`enabled`、`deleted_at`

### 3.2 客户表新增字段

| 字段 | 类型 | 说明 |
|---|---|---|
| park_id | INTEGER | 所属工业园区（外键 → industrial_parks.id，可空） |
| park_remark | TEXT | 园区内位置补充说明（如「东区 3 号门」「二期厂区」） |

**设计说明**：客户与园区是**多对一**（一个客户属于一个园区）。若将来需要多对多，再补关联表；当前按最简单的多对一实现，符合"手动划归"的语义。

### 3.3 结构版本

数据库结构版本 **v2 → v3**，走已有的迁移框架（自动备份 + 逐级迁移 + 幂等），不影响现有数据。

## 五、技术难点与应对（按难度排序）

### 🔴 难点 1：园区坐标的获取（最费时间，非技术难度）

**问题**：84+ 个园区没有现成的坐标数据，且无法通过接口批量获取。

**应对**：
- 软件做成**你录一个用一个**：下拉框已有全部园区名称，随时可归档；坐标什么时候补都可以
- 提供「在线地图核对」一键跳转，找到园区后复制坐标粘回，**单个园区约 30 秒**
- 支持 GCJ-02 / BD-09 自动转换，从高德/百度复制的高德坐标可直接粘贴
- 预置少数高频园区的近似坐标（**明确标注为"估算值，建议校准"**）

**成本估算**：软件侧零额外成本（就是录入功能）；你自己的数据整理时间取决于要多少园区。**建议先只补你最常打交道的 10~20 个**。

### 🟡 难点 2：客户地址 → 园区 的匹配只能是"辅助推荐"

**问题**：想"自动判断客户属于哪个园区"，需要园区边界（没有）或地理围栏（没有）。用"最近园区"推断**会出错**——两个园区可能相隔几公里，客户可能属于 A 却离 B 更近；而且很多客户根本不在园区里（如设计院、贸易商、市政单位）。

**应对**：**坚持手动指定为主**（这也正是你的要求），只提供「按坐标推荐最近的 3 个园区」作为辅助，且**不自动写入**，必须你点选确认。同时对非园区类客户（设计院 / 贸易商 / 市政单位）不强制归属。

### 🟡 难点 3：同一园区内多客户点位重叠

**问题**：同一园区内 10 个客户，如果都按园区坐标画点，会完全重叠成一坨。

**应对**：园区图层与客户图层**分离**——地图上园区是一个点，客户按各自坐标画点；重叠处理用 ECharts 的图元偏移（spider 展开）或简单聚合显示「N 家客户」。**默认按园区聚合**，点击园区才展开。

### 🟢 难点 4：园区地图标签拥挤

**问题**：84 个园区全画在图上是密密麻麻一片标签，没法看。

**应对**：
- 默认**只显示有客户的园区**（0 客户的园区折叠为浅灰小点或隐藏）
- 标签按缩放层级显示：缩小时只显示客户数 ≥ 3 的园区，放大后逐步显示全部
- 提供级别筛选（只看国家级 / 只看化工园区）

### 🟢 难点 5：坐标精度与坐标系

**问题**：园区坐标可能来自不同来源（高德 GCJ-02、百度 BD-09、政府文件 WGS84），混用会出现数百米偏移。

**应对**：阶段六已实现本地坐标转换算法；园区表增加 `coord_source` 字段记录来源，便于日后批量校准。几百米误差对"看分布"这个目的可接受，界面会注明「坐标为近似值」。

### 🟢 难点 6：园区名录的权威性与时效性

**问题**：2018 年公告目录 84 个，2025 年新增 13 个，还可能继续变化。

**应对**：预置数据标注来源与版本日期；园区表**完全可编辑**（增删改），软件不把名录当只读数据。界面注明「名录来源：《中国开发区审核公告目录（2018 年版）》及自治区 2025 年新增名单，可自行增补」。

## 七、合规说明（延续附录 A 的原则）

| 项目 | 做法 |
|---|---|
| 园区名录来源 | 政府公开发布的名录文件（国务院公告目录、自治区发改委公告），属公开政务信息 |
| 园区坐标 | **由你手动标注或导入**，软件不做批量抓取 |
| 园区联系方式 | 仅记录**企业/机构公开总机**，不采集个人姓名与手机号 |
| 地图底图 | 继续使用本地 GeoJSON，断网可用；不做在线瓦片依赖 |
| 审图号 | 界面保留审图号标注位；对外发布前须改用自然资源主管部门标准地图 |

## 九、需要你确认的 3 个问题

1. **预置名录范围**：预置全部 84 个国家级/自治区级开发区名称，还是只预置你常打交道的部分？
   - 全量预置：下拉框很全，但需要滚动查找（会做搜索过滤）
   - 部分预置：更清爽，但可能缺你要的
2. **园区坐标**：先由你手工补 10~20 个常用的（精确），还是我先按县市中心估算一批近似坐标（省事但需校准）？
3. **一个客户是否只属于一个园区**：当前按"一对一"设计（最常见）。如果存在一个客户跨两个园区的情况（如集团在多园区有厂区），需要改成多对多，会增加约 0.5 天。

## 十、结论

| 维度 | 评价 |
|---|---|
| 技术可行性 | ✅ **可行**，无技术障碍。数据表、接口、地图图层、客户归属都是已有模式的复用 |
| 主要难度 | ⚠️ **不在技术，在数据**——园区坐标需要人工录入，软件只能把录入体验做顺（在线地图核对 + 坐标转换 + 批量导入） |
| 与现有功能的关系 | 依赖阶段六地图模块；客户侧改动是纯增量的，不影响已完成功能 |
| 风险 | 低。边界数据缺失已通过"点标注"方案规避；坐标精度有 `coord_source` 字段兜底 |
| 工作量 | 约 **4 天**（若阶段六尚未完成，需先做阶段六） |
