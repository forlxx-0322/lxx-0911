## 五、本阶段修复的缺陷

| # | 缺陷 | 严重度 | 修复方式 |
|---|---|---|---|
| 1 | **单实例判定失效**：第二个进程绑定端口失败时误删 `.run.json`，导致后续所有探测都认不出运行中的服务 | **高** | 引入 `ownsRunFile` 归属标记，非本进程写入的锁文件一律不删；探测逻辑改为「锁文件快速路径 + 端口区间扫描兜底」，不再依赖锁文件存在 |
| 2 | 批处理探针取两次 `%RANDOM%` 导致生成的临时文件名与 PowerShell 实际写入的不一致 | 中 | PowerShell 命令行中直接内联固定文件名 |
| 3 | 批处理缺少 `nul` 设备重定向 | 低 | 补上 `>nul 2>nul` |

## 六、开发过程中定位并固化的技术结论

1. **`.bat` 必须由 Node 以 UTF-8 无 BOM + CRLF 写出**。用 PowerShell here-string 生成会把中文全角冒号等字符破坏，cmd 报 `'??：客户管理系统' is not recognized`。已固化为 `tools/make-bats.js`，不再手写 .bat。
2. **`node:sqlite` 在 Node 24.21 为稳定 API**，无实验性警告；磁盘库 WAL 生效；中文读写、1000 条批量写入与聚合均正常。
3. **沙箱/受限环境下 Node 子进程不能使用管道 stdio**（`execFileSync` 默认管道会 EPERM），需改用 `stdio:'inherit'` 或重定向到文件。
4. **`cmd /c "路径" > out` 在含连字符的目录名下会解析失败**，需写成 `cmd /c call 路径 > out`。
